# Data dictionary

| Table | Key fields | Purpose and integrity rule |
|---|---|---|
| `users` | `id`, `email`, `password_hash` | User identity; email is unique and only password hashes are stored. |
| `roles` | `id`, `name` | Allowed roles: `RESEARCHER`, `ADMIN`. |
| `user_roles` | `user_id`, `role_id` | Many-to-many assignment with composite primary key. |
| `vulnerability_reports` | `id`, `reporter_id`, `status`, `severity` | Authoritative report; title and description cannot be blank. |
| `report_status_history` | `report_id`, `from_status`, `to_status` | Immutable lifecycle record generated by a trigger. |
| `patches` | `report_id`, `reference` | Remediation history; one reference cannot repeat for a report. |
| `bounty_payouts` | `report_id`, `amount`, `reference` | Ledger; one payout per report, positive amount, unique reference. |
| `audit_logs` | `actor_id`, `action`, `entity_id` | Auditable record of sensitive actions. |

## MongoDB evidence document

`report_evidence` has `_id`, `reportId`, `submittedByUserId`, `reproduction`, `affectedComponents`, `technicalMetadata`, `sanitizedPocNotes`, `createdAt`, and `updatedAt`. It stores safe, flexible evidence only; it never stores credentials or executable exploit payloads.
